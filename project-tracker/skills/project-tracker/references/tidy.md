# Tidy-up on request

A sweep of the pages the user asks for, at the scope they name. Without such a request, pages are tidied one item at a time as the work goes (SKILL.md → **Keeping pages tidy**).

Started by the user asking to tidy something: a task ("tidy TSK-7"), a milestone with its tasks ("tidy MLS-6"), a whole project. That is the request itself.

**Inputs:** the scope the user names, and each item's page, fetched fresh.

## Steps

1. Go item by item in the plan's order: the project page first when the scope is the project, then each milestone followed by its tasks, by `Order`.
2. On each item, look for the drift SKILL.md → **Keeping pages tidy** lists, and write its tidy-up in the form given there.
3. Three items per reply, each item's tidy-up proposed and written on the user's yes (SKILL.md → **Propose, then write**), and say how many items are left: the user reads a sweep between other work, and three items is what one reply can carry.

A field or description that contradicts the history is not a tidy-up: ask about it at once, as SKILL.md says.

## Output

Each reply: up to three items' tidy-ups, proposed or written, and how many items are left.

## Off limits

Items outside the scope named; a tidy-up written without the user's yes to it.
